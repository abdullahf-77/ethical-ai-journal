# Record Schema

Defined in code at `pipeline/storage/schema.py` (the `Record` dataclass) — this
document is the field-level reference for a frontend or reviewer consuming
`data/exports/*.json` or the Google Sheets storage backend.

| Field | Type | Meaning |
|---|---|---|
| `id` | string | Stable id. Derived from a SHA1 hash of the normalized DOI when one exists, otherwise `source::normalized_title`. Deterministic — the same paper always gets the same id across pipeline re-runs. |
| `title` | string | Paper title, whitespace-normalized. |
| `authors_first2` | array\<string\> | First up to 2 author names, in the order the source API returned them. |
| `author_count` | integer | Total number of authors (may exceed `len(authors_first2)`). |
| `link` | string \| null | A URL to the paper (landing page, abstract page, or DOI resolver — whichever the source API gave). |
| `doi` | string \| null | Normalized DOI (lowercased, no `https://doi.org/` prefix). Null if the source didn't provide one. |
| `source` | string | Which discovery API found this record: `arxiv`, `semantic_scholar`, `openalex`, or `crossref`. |
| `publish_date` | string \| null | ISO-ish date string. Precision varies by source — `YYYY-MM-DD` when available, sometimes only `YYYY`. |
| `abstract` | string \| null | Raw abstract text from the source (whitespace-normalized; OpenAlex's inverted-index format is reconstructed, Crossref's JATS-tagged abstracts are stripped to plain text). |
| `ai_summary` | string \| null | 2-3 sentence neutral summary generated by the LLM confirmation pass. Falls back to the raw abstract if the LLM call failed. |
| `domains` | array\<string\> | **Real JSON array**, never a joined string. Top-domain ids (`TD1`-`TD7`) the paper was classified into. See `taxonomy/taxonomy_v2_7domains.json`. Empty for excluded records. Multi-label: a paper can carry more than one. |
| `subdomains` | array\<string\> | **Real JSON array.** Specific subdomain names (from the 15-domain / 286-subdomain tier) the paper was classified into. Empty for excluded records. |
| `confidence` | float (0-1) | The LLM confirmation pass's stated confidence in the final classification decision. |
| `rationale` | string \| null | Short LLM-authored justification for the classification (or for excluding the paper). Suffixed with `[LLM overrode embedding shortlist]` when the LLM's final domains differed from what the embedding pre-filter shortlisted — this is intentionally visible, not silently dropped. |
| `taxonomy_version` | string | Which taxonomy version this classification was made against. Currently always `"v2"` (see `taxonomy/taxonomy_v2_7domains.json` / `taxonomy_v2_grouping_rationale.md`). Exists so future taxonomy revisions don't silently invalidate old classifications. |
| `review_status` | string enum | One of `classified` (confidence >= `PIPELINE_REVIEW_THRESHOLD`, default 0.55), `needs_review` (relevant but below the confidence threshold — the human review queue), or `excluded` (LLM judged it unrelated to all 7 domains; kept for audit, not deleted). |
| `date_added` | string | ISO 8601 UTC timestamp of when this record was created by the pipeline. |

## Dataset split

- `data/exports/classified.json` — all records with `review_status` in `{classified, needs_review}`. This is the "relevant" set.
- `data/exports/excluded.json` — records the LLM judged unrelated to all 7 domains. Kept, not deleted, so exclusions are auditable.
- `data/exports/all_records.json` — the union of the two, for convenience.
- `data/exports/manifest.json` — generation timestamp, taxonomy version, and per-status counts.

## Storage backend (source of truth)

Google Sheets (see README for why). Two worksheets, `classified` and
`excluded`, mirroring the same split. Array fields (`domains`, `subdomains`,
`authors_first2`) are stored as JSON-array strings in a single cell (e.g.
`["TD1", "TD4"]`) since a spreadsheet cell can't hold a native array — they
are parsed back into real Python lists on read via
`pipeline/storage/sheets_store.py`, and are always real arrays in the JSON
export. This is not the same as semicolon-joining: it round-trips losslessly
and is unambiguous with values that themselves contain commas or semicolons.
